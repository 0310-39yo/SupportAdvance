# WinTrial 準拠修正計画

作成日: 2026-09-26
根拠: [20260926_WinTrial_準拠調査報告.md](../Reports/20260926_WinTrial_準拠調査報告.md)
前提: WpfTrial の修正計画（[20260926_WpfTrial_MVVM準拠修正計画.md](20260926_WpfTrial_MVVM準拠修正計画.md)）の Phase 1〜5 が完了していること

## 方針

- 各 Phase は単独コミット。CLAUDE.md のルールにより、着手前にユーザー承認を得る
- 共通化した ViewModel の動作は、既存の WpfTrial.Tests（ViewModel テスト）で引き続き保証する
- 画面の見た目・動作は実機で確認する（この環境では起動確認ができないため、変更ごとに手動スモークテストを依頼する）

## Phase A: 未使用コードの整理と判断（W-3）

判断が必要な項目のため、先に方針を確認する。

| 項目 | 選択肢 |
|---|---|
| `Form1View`（到達不能） | (1) MainWindow から開く導線を作る／(2) 試作画面として残し DI 登録のみ／(3) 削除 |
| `MainWindowViewModel`（空・未使用） | (1) MainWindow のタブ・ナビゲーション用に実装／(2) 削除 |
| `MainWindow`（ViewModel なし） | 上記の判断に従う。不要な `using` と空の `Load` ハンドラは整理 |

## Phase B: ViewModel の共通化（W-1・W-2）

- `Form1ViewModel` と `LoginWindowViewModel`／`LoginDialogViewModel` を `Presentation.Shared/ViewModels` へ移動して共通化
  - WpfTrial・WinTrial の双方から同一クラスを使用
  - WpfTrial の Phase 1・5 の修正（`IAppSettings` 化、`DepartmentNames` クリア、例外処理の統一、`_camelCase` 命名）がそのまま WinTrial に適用される
  - `Shared.csproj` に必要な参照（Authentication.Application、IntegrationPrototype.Application）を追加。参照方向は Presentation → Application で許可された範囲
- `WpfTrial.Tests` の該当テストを `Shared` 用のテストプロジェクトへ移すか、参照先を更新（テスト内容は変更しない）
- DI 登録の型名変更に追随（`LoginDialogViewModel` を使う `LoginDialog` は共通の Login ViewModel を受け取る）
- 検証: 全ビルド・全テスト、ログイン → メイン画面のスモークテスト（WinTrial／WpfTrial の両方）

Phase B が完了すると、W-2 の指摘（WpfTrial で修正済みの問題）は自動的に解消される。Phase A の判断結果によっては、Phase C の C-4 の対象範囲が変わる。

## 実施結果（2026-09-26）

ビルドと全テストは合格。**WinForms 画面の実機確認は未実施**（下記「実機で確認が必要な項目」を参照）。

### Phase A の判断結果

- ナビゲーションに項目を表示し、クリックでプレースホルダー画面（タブ）を開く（WpfTrial と同じ動作）
- `MainWindowViewModel` は実装する

### Phase B: ViewModel の共通化（実施済み）

- `Form1ViewModel`、`LoginViewModel`（`LoginWindowViewModel`／`LoginDialogViewModel` を統合）、`MainWindowViewModel`、`TabItemViewModel`、`EmptyTabContentViewModel` を `Presentation.Shared/ViewModels` に移動（WpfTrial・WinTrial で共用）
- `Shared.csproj` に Authentication.Application／IntegrationPrototype.Application を追加
- `MainWindowViewModel` に `CloseTabCommand` を追加（ItemsSource を持たない WinForms が、タブの終了を ViewModel に反映するため）
- テストは `tests/Presentation/Shared.Tests` に移動（旧 WpfTrial.Tests。23 テスト）

### Phase C（実施済み）

- C-1 `lblError.Visible` は `Binding.Format` で「メッセージが空でない場合のみ表示」に変換
- C-2 `IsNotLoading` は廃止し、ログインボタンの `Enabled` を `IsLoading` の反転（`Binding.Format`）で配線
- C-3 DI 登録を `AddWinTrialModules()` に集約。`??`（到達しないコード）は削除。ただし `ServiceProviderServiceExtensions.GetService<>(...)` の静的呼び出しは Syncfusion の `System.ServiceExtensions` との名前衝突を避ける回避策のため、意図的に維持（コメントを追記）
- C-4 `Form1View` から動作確認用ログ・不要なフィールド・`IAppLogging`／`IAppSettings` の注入を削除
- C-5 `MainWindow` のテーマ（Office2016DarkGray）は維持し、WpfTrial と異なる旨をコメントで明示
- `MainWindow`: NavigationDrawer に項目（顧客一覧・顧客登録・受注一覧・受注登録）を表示し、クリックで MDI 子フォーム（`EmptyTabForm`、「（未実装）」表示）をタブとして開く。WinForms の NavigationDrawer は階層を持てないため、WpfTrial の階層メニューのうち葉ノードのみを並べた

### Phase D（実施済み）

- `PresentationArchitectureTests`: Shared の ViewModel が View／UI 型に依存しないこと、WpfTrial／WinTrial が ViewModel を独自に定義しないこと、WinTrial の View が UI 型に依存することの検出（空振り防止）を追加

### 実機確認後の追加対応

- NavigationDrawer は既定で閉じているため、表示後に開き常時表示にした。ウィンドウのリサイズで項目が消えたため、サイズ変更のたびに大きさを合わせて開き直す
- 親項目（顧客管理・受注管理）が表示されなかったため、見出し項目（クリックしても何もしない）と字下げした子項目を平らに並べて階層を表現
- 顧客一覧をクリックすると、WinTrial・WpfTrial とも `Form1ViewModel` の画面（Form1View）を仮として表示。WpfTrial の Form1View は Window から UserControl に変更し、DataTemplate で対応付け。WinTrial は MDI 子フォームとして表示。他の項目は「（未実装）」のまま

- 開き直す対応でもリサイズで項目が消えたため、NavigationDrawer の使用をやめ、階層を持てる標準の `TreeView` を左側に固定配置する方式に変更（親項目「顧客管理」「受注管理」は展開／折りたたみ、子項目のクリックまたは Enter でタブを開く）

- 標準の `TreeView` で動作を確認できたため、Syncfusion のテーマが効く `TreeViewAdv` に置き換え（項目構成・クリック／Enter の動作は同じ）

### 実機で確認が必要な項目

- WinTrial のログイン → MainWindow 表示
- NavigationDrawer に項目が表示されること（既定で折りたたまれている可能性があり、その場合は ToggleDrawer などの追加対応が必要）
- 項目クリックでタブ（MDI 子フォーム）が開き、同名の項目を再度クリックすると既存タブが前面に出ること
- タブを閉じたときに ViewModel の選択タブが更新されること
- ログイン画面でエラー時にだけエラーラベルが表示されること、ログイン処理中にボタンが無効になること
