# Phase 2 テスト整備 修正実装計画書

**作成日:** 2026-09-16  
**対象読者:** 別セッションの AI エージェント  
**位置づけ:** Phase 2（Domain層テスト・ドキュメント補完）の緊急修正  
**前提:** 134+ コンパイルエラーが発生中。本計画書に基づいて段階的に修正し、ビルド成功を達成する

---

## 概要

Phase 2 で別 AI が生成したテストコードが、Domain 実装との API ズレにより大量のコンパイルエラーを引き起こしています。本計画書は、**最小限の変更でビルド green を達成する** 修正手順を段階化したものです。

修正は **5 段階** に分けて実施し、各段階でビルドを検証します。

---

## 修正戦略

### 基本原則

1. **テストコード削除ではなく修正**（ビジネスロジック検証を失わない）
2. **段階的修正**（各段階ごとに `dotnet build` で検証）
3. **API の「実装側」を正とする**（テストが実装に合わせる）

### 修正順序

| Stage | Priority | 対象ファイル数 | 対象エラー | 概要 |
|-------|----------|---|---|---|
| **Stage 1** | P0 Critical | 2 | EmployeeNumber, EmploymentStatus クラス定義 | テスト メソッドを `public class` 内に移動 |
| **Stage 2** | P1 High | 8+ | RowId コンストラクタ → `.From()` | 4 RowId クラスの全テストを修正 |
| **Stage 3** | P2 Medium | 3 | Person/DepartmentMembership Entity テスト | 実装欠落クラスのテストをコメント化 or 削除 |
| **Stage 4** | P2 Medium | 6+ | ValueObject TryFrom/Date プロパティ | using ディレクティブ追加、プロパティアクセス修正 |
| **Stage 5** | P3 Low | 3 | EmployeeRetiredEventTests, DepartmentMembershipTests | async/await, using, 変数名修正 |

## 注意事項

### 削除前の確認

テストコードを削除する前に、必ず以下を確認してください：

1. **Entity が実装されているか:**
   ```bash
   find src/Contexts/Employee -name "Person.cs"
   find src/Contexts/Employee -name "DepartmentMembership.cs"
   find src/Contexts/Employee -name "EmployeeRetiredEvent.cs"
   ```

2. **結果がなければ削除 OK**

3. **結果があれば、テスト修正を試みる**（実装 API に合わせて）

### RowId の `.From()` vs コンストラクタ

SupportAdvance では **すべての RowId が `.From()` static メソッドを使う** が原則：

```csharp
// ✓ 正しい
var id = EmployeeRowId.From(123L);

// ❌ 間違い
var id = new EmployeeRowId(123L);
```

RowId のコンストラクタは通常 private です。

## 予期されない エラーが出た場合

修正中に予期しないエラーが出た場合、以下を確認：

1. **エラーメッセージをメモ**（ファイル名、行番号、エラーコード）

3. **エラーの「真の原因」を特定**（クラス未実装 vs API ズレ vs using 欠落）
4. **対応:** 削除 or 修正を判断
