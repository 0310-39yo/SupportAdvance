### 【高優先度 - フェーズ2】

#### 改善項目 3: Presentation → Infrastructure の型レベル検証

**現状:**
- 詳細分析レポート 96-108行で「WinTrial は ProjectReference で Infrastructure に到達可能だが、Program.cs のみでの使用」と記載
- NetArchTest で検証テスト実装予定だが、Presentation プロジェクトがクロスプラットフォーム非対応のため、実装をスキップ

**実装課題:**
- WinTrial, WpfTrial は Windows 固有プロジェクト（`net10.0-windows`）
- テストプロジェクト（`net10.0`）から参照できない互換性問題
- 代替策：テストを別途 Windows 環境で実行する構成が必要

**推奨対応:**
```
方針A: CI/CD で Windows エージェントを使用
  - テストプロジェクトを net10.0-windows ターゲットにする
  - GitHub Actions で Windows ランナーで実行
  - 工数：2時間

方針B: 型検査を簡略化（当面）
  - Infrastructure 名前空間への using を Grep で検査
  - Program.cs 以外のファイルで参照があれば違反
  - 工数：30分（スクリプト化）

方針C: 自動検証をスキップ（リスク許容）
  - 引き続きコードレビュー（目視）に依存
  - NetArchTest のテストケース 4 は実装しない
  - 工数：0
```

**現在の判定:** **方針B を推奨**（当面）

**改善内容:**
Presentation → Infrastructure 参照チェック用スクリプト
```bash
# Program.cs 以外で Infrastructure を参照していないか確認
grep -r "using.*Infrastructure" src/Presentation --include="*.cs" \
  | grep -v Program.cs | grep -v ".vshistory" && \
  echo "❌ VIOLATION: Infrastructure used outside Program.cs" || \
  echo "✅ OK: Infrastructure only in Program.cs"
```

**工数見積:** 30分（スクリプト化 + ドキュメント）  
**優先度:** 🔴 **高**（高リスク領域の検証）  
**実施時期:** 次フェーズ（別計画）  
**状態:** 📅 **計画中**

**A. Application層の例**
```csharp
// src/Contexts/Samples/CarPreferences.Application/UseCases/UpdateCarPreferenceUseCase.cs
// Use Case 実装例を詳細化
public class UpdateCarPreferenceUseCase : IUseCase<UpdateCarPreferenceCommand, UpdateCarPreferenceResponse>
{
    private readonly ICarPreferenceRepository _repository;
    private readonly IDomainEventPublisher _eventPublisher;
    private readonly IAppLogging<UpdateCarPreferenceUseCase> _logger;

    public UpdateCarPreferenceUseCase(...)  { }

    public async Task<UpdateCarPreferenceResponse> ExecuteAsync(UpdateCarPreferenceCommand request)
    {
        _logger.LogInformation("Executing UpdateCarPreference...");
        var preference = await _repository.GetByIdAsync(request.Id);
        preference.UpdateModel(request.NewModel);
        await _eventPublisher.PublishAsync(preference.DomainEvents);
        return new UpdateCarPreferenceResponse { Success = true };
    }
}
```

**B. Infrastructure層の例**
```csharp
// src/Contexts/Samples/CarPreferences.Infrastructure/Repositories/CarPreferenceRepository.cs
// Repository 実装例を詳細化
public class CarPreferenceRepository : ICarPreferenceRepository
{
    private readonly IDbConnection _connection;
    private readonly ICurrentUserService _currentUser;

    public async Task<Car> GetByIdAsync(CarId id)
    {
        var dto = await _connection.QuerySingleOrDefaultAsync<CarDto>(
            "SELECT * FROM cars WHERE id = @Id AND deleted_at IS NULL",
            new { Id = id.Value });
        
        return dto?.ToDomain();
    }

    public async Task SaveAsync(Car car)
    {
        var dto = CarMapper.ToDto(car);
        await _connection.ExecuteAsync(
            @"UPDATE cars SET model = @Model, updated_at = @UpdatedAt, updated_by = @UpdatedBy
              WHERE id = @Id",
            new {
                Id = dto.Id,
                Model = dto.Model,
                UpdatedAt = DateTime.UtcNow,
                UpdatedBy = _currentUser.UserId
            });
    }
}
```

**C. Domain層の例**
```csharp
// src/Contexts/Samples/CarPreferences.Domain/Entities/Car.cs
// Domain Entity 実装例を詳細化
public class Car : AggregateRoot<CarId>
{
    public CarModel Model { get; private set; }
    public CreatedAt CreatedAt { get; private set; }
    public UpdatedAt? UpdatedAt { get; private set; }

    public void UpdateModel(CarModel newModel)
    {
        if (newModel == Model)
            return; // 変更なし

        Model = newModel;
        UpdatedAt = UpdatedAt.TryFrom(LocalDateTime.Now); // ドメインイベント発行
        RaiseDomainEvent(new CarModelUpdatedEvent(Id, newModel));
    }
}
```
