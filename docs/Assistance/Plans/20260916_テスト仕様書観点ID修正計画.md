# テスト仕様書観点ID修正計画

**日付:** 2026-09-16  
**対象:** 単体テスト仕様書 41個（特に観点ID定義なし23個）  
**目的:** 全仕様書の観点ID体系を VO-形式に統一化

---

## 1. 観点ID体系の標準化

### 1.1 VO-形式の標準パターン

基準となる PersonRowId_単体テスト仕様書の観点ID体系：

```
VO-GEN-xx  : Generation（生成）— From, New 等のファクトリメソッド
VO-TRY-xx  : TryFrom（安全な生成）— bool 戻り値のファクトリ
VO-DBVAL-xx: DB値変換 — TryFromDbValue, FromDbValue
VO-EQ-xx   : Equals — 等価判定で true となるケース
VO-NE-xx   : Equals — 非等価判定で false となるケース
VO-HC-xx   : GetHashCode — ハッシュ整合性
VO-OP-xx   : 演算子 — ==, !=, <, > などのオーバーロード
VO-TS-xx   : ToString — 文字列化
```

---

## 2. 仕様書種別による観点ID体系の適用ガイド

### A. ValueObject 仕様書（RowId, Audit等）

**対象:** PersonRowId, CreatedAt, EmployeeRowId など

**適用観点:**
```
VO-GEN-01: From(有効値) で正しく生成される
VO-GEN-02: From(無効値) で例外が発生する
VO-TRY-01: TryFrom(有効値) で true を返す
VO-TRY-02: TryFrom(無効値) で false を返す
VO-DBVAL-01: TryFromDbValue(有効値) で true を返す
VO-EQ-01: 同じ値を持つ 2 つのオブジェクトは等価
VO-EQ-02: 自己参照は等価
VO-NE-01: 値が異なれば非等価
VO-NE-02: null との比較は非等価
VO-HC-01: Equals=true のハッシュ値は同一
VO-HC-02: HashSet / Dictionary で正しく動作
VO-OP-01: == 演算子が正しく機能
VO-OP-02: != 演算子が正しく機能
VO-TS-01: ToString が仕様通りの形式を返す
```

**該当仕様書数:** 15個（現在 VO-形式）

**修正:** なし（既に準拠）

---

### B. Entity 仕様書（Employee, Person等）

**対象:** Employee_単体テスト仕様書, Person_単体テスト仕様書 等

**適用観点:**
```
VO-CONS-01: コンストラクタで正しくインスタンスが生成される
VO-CONS-02: 必須フィールドが null なら例外が発生する
VO-PROP-01: 各プロパティが正しい値を返す
VO-PROP-02: プロパティは読み取り専用（再代入できない）
VO-METHOD-01: ドメインメソッド A が正しく動作する
VO-METHOD-02: ドメインメソッド B が正しく動作する
VO-VALID-01: 値が無効な場合、例外 / 検証エラーが返される
VO-VALID-02: 値が有効な場合、成功する
VO-EQ-01: 同じ ID を持つ Entity は等価
VO-NE-01: 異なる ID の Entity は非等価
VO-EVNT-01: ドメインイベントが正しく発行される
```

**該当仕様書数:** 約8-10個

**修正:** 高優先度 — 観点ID テーブルを追加

---

### C. UseCase 仕様書（CreateEmployeeUseCase等）

**対象:** Application_単体テスト仕様書（各BC）内の UseCase 実装

**適用観点:**
```
VO-EXEC-01: 有効な Request で正しく実行される
VO-EXEC-02: Request が null なら例外が発生する
VO-RESULT-01: 戻り値が期待通りである
VO-RESULT-02: 複数の Request を実行できる（データドリブン）
VO-ERROR-01: 無効な Input で例外が発生する
VO-ERROR-02: 業務ルール違反で例外が発生する
VO-STATE-01: UseCase 実行後の状態が正しく更新される
VO-EVNT-01: ドメインイベント が発行される
VO-SIDE-01: 副作用（Repository 呼び出し等）が正しく実行される
```

**該当仕様書数:** 約3-5個（Application 層仕様書）

**修正:** 高優先度 — テストケース箇条書きを観点ID テーブルに変換

---

### D. QueryService 仕様書

**対象:** EmployeeQueryService など Application の Query クラス

**適用観点:**
```
VO-QUERY-01: GetByIdAsync(存在する ID) で Entity を返す
VO-QUERY-02: GetByIdAsync(存在しない ID) で null を返す
VO-QUERY-03: GetByCondition で複数の結果を返す
VO-FILTER-01: フィルタ条件が正しく適用される
VO-SORT-01: ソート順序が正しい
```

**該当仕様書数:** 約2-3個

**修正:** 中優先度

---

### E. Repository 仕様書（Infrastructure）

**対象:** EmployeeRepository, DepartmentRepository など Infrastructure 層実装

**適用観点:**
```
VO-CRUD-01: SaveAsync で Entity を保存できる
VO-CRUD-02: GetByIdAsync で保存した Entity を復元できる
VO-CRUD-03: UpdateAsync で Entity を更新できる
VO-CRUD-04: DeleteAsync で Entity を削除できる
VO-AUDIT-01: 監査フィールド（CreatedAt/UpdatedAt等）が自動設定される
VO-CONC-01: GetLatestByXXX で最新レコードを取得できる
VO-TXRX-01: 複数テーブル集約でトランザクション一貫性が保たれる
```

**該当仕様書数:** 約3-5個（Infrastructure 層仕様書）

**修正:** 中優先度 — 既に一部テストケース列挙されている場合は観点ID へ変換

---

### F. Mapper 仕様書

**対象:** EmployeeMapper, PersonMapper など

**適用観点:**
```
VO-MAP-01: Domain Entity → DbModel への変換が正しい
VO-MAP-02: DbModel → Domain Entity への変換が正しい
VO-MAP-03: null 値の処理が正しい
VO-MAP-04: 複数テーブルの集約マッピングが整合性を保つ
VO-TYPE-01: 型変換（DateTime ↔ LocalDateTime等）が正しい
```

**該当仕様書数:** 約1-2個

**修正:** 低優先度

---

### G. Service 仕様書（PasswordHashService等）

**対象:** PasswordHashService, CorrelationContext など

**適用観点:**
```
VO-HASH-01: ハッシュ生成が正しく実行される
VO-HASH-02: ハッシュ検証が成功する（正しい入力）
VO-HASH-03: ハッシュ検証が失敗する（間違った入力）
VO-SECURITY-01: PBKDF2/Salt 要件を満たす
VO-PERF-01: 処理時間が許容範囲内
```

**該当仕様書数:** 約2-3個

**修正:** 中優先度

## 6. 実装ガイドライン

### 観点ID割り当てのコツ

1. **テストコードを読む** — 何をテストしているか把握
2. **観点を分類** — VO-CONS, VO-PROP, VO-METHOD など
3. **連番を振る** — VO-CONS-01, VO-CONS-02, ...
4. **テスト実装列で対応付け** — テストファイル::メソッド名 を記載

### 表記例

```markdown
| VO-CONS-01 | 有効なパラメータでインスタンスが生成される | ✅ PersonTests.cs::TestConstructor |
```
