## 1. テストメソッド命名規則（新標準）

### 命名形式

```
VO_<観点タイプ>_<観点番号>_<テスト名>

例：
- VO_EXEC_01_CreateEmployee_WithValidRequest_ReturnsEmployeeDto
- VO_CRUD_01_SaveAsync_WithValidEntity_PersistsToDb
- VO_MAP_01_ToDbModel_WithValidEntity_MapsAllFields
- VO_HASH_01_Hash_WithValidPassword_GeneratesHash
```

### 構成要素

| 要素 | 例 | 説明 |
|------|-----|------|
| **VO_** | `VO_` | 観点ID 接頭辞（固定） |
| **観点タイプ** | `EXEC`, `CRUD`, `MAP`, `HASH` | 観点の分類 |
| **番号** | `01`, `02`, ... | 観点内でのシーケンス番号 |
| **テスト名** | `CreateEmployee_WithValidRequest_ReturnsEmployeeDto` | テスト内容の説明 |

## 6. リスク と対策

### リスク1: テスト実行エラー

**原因:** メソッド名変更後、テストが実行されない  
**対策:** 各ステップ後に `dotnet test` で確認

### リスク2: メソッド名の重複

**原因:** 同じ名前のメソッドが複数存在  
**対策:** 命名規則を厳守、IDE の検索で確認

### リスク3: 既存参照の破損

**原因:** テストメソッド名が変わると、他の場所からの参照が破損  
**対策:** IDE の「すべての参照をリネーム」機能を活用
