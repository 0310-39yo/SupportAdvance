# アイコン 利用ガイド

WpfTrial・WinTrial で使うアイコンの方式と、アイコンを追加するときの手順をまとめる。

## 方針

| 項目 | 内容 |
|---|---|
| アイコンの種類 | Fluent UI System Icons（Microsoft、MIT ライセンス） |
| 方式 | アイコンフォント 1 ファイルを WPF／WinForms で共用し、アイコンを文字として描画する |
| 理由 | 拡大縮小・文字色の変更・高 DPI に強い。フォントファイルが 1 つで済み、SVG の変換や画像の書き出しが不要。WPF と WinForms で同じ対応表を使える |
| 実体の置き場 | `src/Presentation/Shared/Assets/Fonts/`（フォント本体、ライセンス文、README） |
| 名前の管理 | `AppIcon`（用途を表す名前）と `FluentIconCatalog`（字形の対応表）を `Presentation.Shared/Icons` で一元管理 |

## 構成

```
Presentation.Shared
├── Assets/Fonts/FluentSystemIcons-Resizable.ttf   ← フォントの実体（1 ファイルのみ）
├── Assets/Fonts/LICENSE.txt                       ← MIT ライセンス文（再配布時に同梱）
├── Icons/AppIcon.cs                               ← 用途を表す名前（enum）
└── Icons/FluentIconCatalog.cs                     ← AppIcon → コードポイントの対応表（UI 非依存）

WpfTrial
├── WpfTrial.csproj                                ← フォントを Resource としてリンク
└── Controls/FluentIcon.cs                         ← アイコンを表示するコントロール

WinTrial
├── WinTrial.csproj                                ← フォントを埋め込みリソースとしてリンク
└── Icons/FluentIconFont.cs                        ← フォントを読み込み、アイコンの画像を作成
```

- フォントの**コピーを置かない**。各アプリは csproj の `Link` で Shared の 1 ファイルを取り込む
- Shared は UI に依存しない。描画は各アプリが担当する

## 使い方

### WpfTrial

```xml
xmlns:controls="clr-namespace:SupportAdvance.Presentation.WpfTrial.Controls"

<controls:FluentIcon Icon="Save" FontSize="18" Foreground="#FF555555" />
```

- 大きさは `FontSize`、色は `Foreground` で指定する

### WinTrial

```csharp
using var bitmap = FluentIconFont.CreateBitmap(AppIcon.Save, pixelSize: 16, color: ForeColor);
imageList.Images.Add(bitmap);
```

- 高 DPI では `pixelSize` を `16 * DeviceDpi / 96` のように拡大する（`MainWindow` の例を参照）

## アイコンを追加する手順

1. `AppIcon` に、**見た目ではなく用途を表す名前**を追加する（例: `Save`、`Customers`）
2. 配布元の `FluentSystemIcons-Resizable.json`（https://github.com/microsoft/fluentui-system-icons の `fonts` フォルダー）で、使いたいアイコンのコードポイントを調べる
   - キーは `ic_fluent_<名前>_20_regular`（例: `ic_fluent_save_20_regular` → 57241 = 0xEF99）
   - アイコンの見た目は https://fluenticons.co/ などで確認できる
3. `FluentIconCatalog` の対応表に「`AppIcon` の値 → コードポイント」を 1 行追加し、末尾のコメントにアイコン名を書く
4. `Shared.Tests` の `FluentIconCatalogTests` を実行する（追加漏れ、コードポイントの重複、範囲外の値を検出する）
5. 各画面で `FluentIcon`（WPF）／`FluentIconFont`（WinForms）に `AppIcon` を指定する

## 運用ルール

- 画面のコードに**コードポイントを直接書かない**。必ず `AppIcon` を経由する（アイコンの差し替えを対応表だけで済ませるため）
- 同じ用途には同じ `AppIcon` を使い回し、似た用途のアイコンを増やしすぎない
- フォントを新しい版に差し替える場合は、既存のコードポイントが同じアイコンを指していることを、配布元の JSON で確認する（版によりコードポイントが変わることがある）
- ライセンス（MIT）の著作権表示と許諾文を、配布物に同梱する（`Assets/Fonts/LICENSE.txt`）
- 他のアイコン集（Material Design Icons など）を併用しない。方式を変える場合は、この方針と `Icons` の構成をあわせて見直す

## 既知の制約

- WinForms の NavigationDrawer や Syncfusion の一部のコントロールは、画像（`ImageList`）でアイコンを受け取る。その場合は `FluentIconFont.CreateBitmap` で画像を作成して渡す
- 対応表のコードポイントは、フォントの版（`FluentSystemIcons-Resizable.ttf`）に依存する
