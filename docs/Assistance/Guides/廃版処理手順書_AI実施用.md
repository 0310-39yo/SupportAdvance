# 廃版処理手順書（AI 実施用）

**プロジェクト:** SupportAdvance  
**対象:** AI  
**種別:** 廃版処理手順書  
**版:** 1.0 / 2026-06-26

---

## 0. 本書の目的

本書は、AI が **文書・仕様・設計の変更・削除に伴う廃版処理を自律的に実施するための手順** を定義する。

> **⚠️ 重要制約**  
> 廃版処理はファイル操作を伴う。AI は以下を厳守する。  
> - **実施前に必ず調査結果を人に報告し、承認を得てからファイル操作を行う**  
> - ファイルの移動・削除は人の承認後にのみ実施する  
> - `.cs` ファイル（実装コード）の削除は AI の権限外。人に報告するのみ

---

## 1. 廃版処理が必要になる契機

以下のいずれかが発生した場合、廃版処理の要否を判断する。

| 契機 | 例 |
|------|-----|
| 文書の新バージョン作成 | 技術仕様書 v1.0 → v2.0 に更新 |
| クラス名・メソッド名の変更 | `SampleCreatedAt` → `SampleRegistrationAt` |
| 仕様・設計の廃止 | インターフェースの削除・統合 |
| 項目名・用語の変更 | 文書内のキーワード変更 |

---

## 2. 廃版処理の全体フロー

```
Step 1：廃版判定
    ↓
Step 2：調査（docs/ 配下のドキュメント）
    ↓
Step 3：調査（src/ 配下の実装コード）
    ↓
Step 4：調査結果の報告（人への確認）
    ↓
Step 5：ドキュメントの廃版処理（承認後に実施）
    ↓
Step 6：廃版フォルダの README 更新
    ↓
Step 7：処理結果の報告
```

---

## 3. 各ステップの詳細手順

### Step 1：廃版判定

変更・削除の対象を確定し、以下の情報を整理する。

| 項目 | 内容 |
|------|------|
| 変更の種類 | 新バージョン作成 / 名称変更 / 廃止 |
| 旧キーワード | 検索対象となる旧名称・旧表現 |
| 新キーワード | 新名称・新表現（廃止の場合は「廃止」） |
| 廃版対象ファイル | 旧バージョンとなるファイルのパス |

---

### Step 2：docs/ 配下のドキュメント調査

#### 2.1 旧キーワードの検索

`docs/` 配下の全 `.md` ファイルに対して旧キーワードを検索する。

```
検索対象：docs/**/*.md
検索キーワード：{旧クラス名 / 旧メソッド名 / 旧項目名}
除外対象：廃版フォルダ内（廃版フォルダはヒットしても処理不要）
```

#### 2.2 ヒット箇所の分類

検索でヒットした箇所を以下の 3 種類に分類する。

| 種類 | 判断基準 | 処理 |
|------|----------|------|
| **A：本文・仕様・設計に記載** | 仕様の中心的な記述として旧キーワードが使われている | **廃版処理対象** |
| **B：変更履歴欄のみに記載** | 「旧名称から変更」などの記録として残っている | **処理不要**（記録として正しい） |
| **C：廃版フォルダ内に記載** | 廃版済みファイル内の記述 | **処理不要** |

---

### Step 3：src/ 配下の実装コード調査

`src/` 配下の全 `.cs` ファイルに対して旧シグネチャ・旧クラス名を検索する。

```
検索対象：src/**/*.cs
検索キーワード：{旧クラス名 / 旧メソッド名 / 旧シグネチャ}
```

> **⚠️ 重要**  
> `.cs` ファイルに旧実装が残存していた場合、AI は**削除を行わない**。  
> 「旧実装が残存している」という事実を人に報告するのみとする。

---

### Step 4：調査結果の報告（人への承認依頼）

以下の形式で調査結果を報告し、**ファイル操作の承認を求める**。

---

**【廃版処理調査結果レポート】**

**変更内容：** {旧キーワード} → {新キーワード}

**調査対象：**
- `docs/` 配下 `.md` ファイル（キーワード：{旧キーワード}）
- `src/` 配下 `.cs` ファイル（キーワード：{旧キーワード}）

**廃版処理が必要な箇所（種類 A）：**

| ファイル | 箇所 | 処理内容 |
|----------|------|----------|
| `{ファイルパス}` | {セクション・行の説明} | {本文修正 / 廃版フォルダへ移動} |

**処理不要な箇所：**

| ファイル | 理由 |
|----------|------|
| `{ファイルパス}` | 変更履歴欄のみの記述のため処理不要 |

**実装コードの状況：**

- {旧実装が残存していない / `{ファイルパス}` に旧実装が残存（人の判断が必要）}

**承認依頼：**  
上記の廃版処理を実施してよいでしょうか。

---

### Step 5：ドキュメントの廃版処理（承認後に実施）

人の承認を受けた後、以下の処理を実施する。

#### 5.1 廃版フォルダの確認・作成

廃版対象ファイルが存在するフォルダに `廃版/` サブフォルダがあるか確認する。

```
存在する場合 → そのまま使用
存在しない場合 → 廃版/ フォルダを作成し、README.md を新規作成する
```

**README.md の作成内容（廃版フォルダが新規の場合）**

```markdown
# 廃版ファイル管理 — {フォルダ名}領域

**版:** 1.0
**作成日:** {YYYY-MM-DD}

## 1. 本フォルダの位置づけ

本フォルダ（`{フォルダパス}/廃版/`）は、旧バージョン・廃止済みドキュメントを保管する。

## 2. ファイル名規則

廃版ファイルは以下の形式で命名する。

```
v[廃版時の版番号]_[元のファイル名]_[廃版日].md
```

## 3. 廃版ファイル一覧

| # | ファイル名 | 元のファイル名 | 廃版化日 | 理由 | 後継ドキュメント |
|---|-----------|--------------|--------|------|----------------|
```

#### 5.2 廃版ファイルの移動・改名

廃版対象のファイルを廃版フォルダに移動し、命名規則に従って改名する。

**命名規則：**
```
v{廃版時の版番号}_{元のファイル名}_{廃版日YYYY-MM-DD}.md

例：
  元ファイル：ValueObject技術仕様書.md（v1.0）
  廃版後：v1.0_ValueObject技術仕様書_2026-06-26.md
```

**廃版時の版番号の取得方法：**
- 廃版対象ファイルのヘッダー（`**版:**` 行）から読み取る
- 記載がない場合は `v1.0` とする

#### 5.3 現行ドキュメントの本文修正

種類 A（本文・仕様・設計に旧キーワードが残存）のファイルを修正する。

| 処理 | 内容 |
|------|------|
| 旧キーワードを新キーワードに置き換え | 本文・表・コード例の旧記述を更新 |
| 変更履歴欄への追記 | 「{旧名称} → {新名称} に変更」を記録 |

---

### Step 6：廃版フォルダの README 更新

廃版フォルダの README.md の「廃版ファイル一覧」テーブルに追記する。

```markdown
| {番号} | {廃版後のファイル名} | {元のファイル名} | {廃版日} | {廃版理由} | {後継ドキュメント名} |
```

---

### Step 7：処理結果の報告

以下の形式で処理結果を報告する。

---

**【廃版処理完了レポート】**

**変更内容：** {旧キーワード} → {新キーワード}

**実施した処理：**

| 処理 | 対象ファイル | 内容 |
|------|------------|------|
| 廃版フォルダ作成 | `{パス}/廃版/` | 新規作成（README.md 含む） |
| ファイル移動・改名 | `{旧パス}` → `{新パス}` | v{X.Y}_{ファイル名}_{日付}.md |
| 本文修正 | `{ファイルパス}` | {旧キーワード} → {新キーワード} に変更 |
| 変更履歴追記 | `{ファイルパス}` | §改版履歴に追記 |
| README 更新 | `{廃版フォルダ}/README.md` | 廃版ファイル一覧に追記 |

**処理不要と判断した箇所：**

| ファイル | 理由 |
|----------|------|
| `{ファイルパス}` | {理由} |

**人への申し送り事項：**

- {実装コードに旧実装が残存している場合など、人の判断が必要な事項}
- {なければ「なし」}

## 5. 判断に迷う場合のルール

| 状況 | 対応 |
|------|------|
| 旧キーワードが本文か変更履歴か判断できない | 保守的に「処理対象」として人に確認する |
| 廃版フォルダをどの階層に作るか迷う | 廃版対象ファイルと**同じ階層**に作成する |
| 廃版時の版番号がファイルに記載されていない | `v1.0` として扱い、README に「版番号不明」を記載する |
| 後継ドキュメントが存在しない（廃止の場合） | README の「後継ドキュメント」欄に「廃止（後継なし）」と記載する |

---

## 6. AI が行わないこと（禁止事項）

| 禁止事項 | 理由 |
|----------|------|
| 人の承認なしにファイル操作を行う | 廃版は不可逆操作のため |
| `.cs` ファイルの削除・移動 | 実装コードの管理は人の責任範囲 |
| 廃版判定の最終決定 | 「廃版すべきか」の判断は人が行う |
| `discussion/` フォルダの参照 | docs/CLAUDE.md の禁止事項 |
