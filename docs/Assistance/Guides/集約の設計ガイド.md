## 1. 集約とは

### 定義

**集約** = ビジネスの一貫性を保証するエンティティと値オブジェクトのグループ

```
集約根（AggregateRoot）
  ├─ Entity（子Entity）
  │  ├─ Entity（孫Entity）
  │  └─ ValueObject
  └─ ValueObject
```

### 集約の本質

| 特性 | 説明 |
|------|------|
| **一貫性の単位** | 集約内では常に一貫した状態を保つ |
| **トランザクション境界** | 集約全体を 1回の UPDATE で保存 |
| **エンティティ識別** | 集約根の ID で識別（内部の子は無視） |
| **不変性** | 一度保存したら、次の変更まで状態は不変 |

## 2. 集約の責務と境界

### 集約根（AggregateRoot）の責務

```csharp
public abstract class AggregateRoot<TId> : Entity<TId>, IAggregateRoot
    where TId : notnull, RowId
{
    // 【責務】
    // 1. 子Entity の管理（一貫性保証）
    // 2. ビジネスルールの実装
    // 3. ドメインイベント発行
    // 4. トランザクション境界の明示
}
```

### 集約根と子Entity の違い

| 項目 | 集約根 | 子Entity |
|------|--------|---------|
| **識別** | ID で外部から参照 | 集約根経由でのみアクセス |
| **持続化** | Repository で管理 | 集約根に内包される |
| **生成** | Create() / Reconstruct() | 集約根から生成 |
| **ドメインイベント** | 発行（RaiseDomainEvent） | 親経由で発行 |

## 3. トランザクション境界

### 原則

**1つの集約 = 1回のトランザクション**

```csharp
// ✅ 正しい
public async Task SaveAsync(Employee aggregate)
{
    using var transaction = _connection.BeginTransaction();
    try
    {
        // Employee テーブル更新
        await UpdateEmployeeAsync(aggregate, transaction);
        
        // Person テーブル更新（子Entity）
        await UpdatePersonAsync(aggregate.Person, transaction);
        
        // DepartmentMembership テーブル更新（複数行子Entity）
        await UpdateDepartmentMembershipsAsync(aggregate.DepartmentMemberships, transaction);
        
        transaction.Commit();
    }
    catch
    {
        transaction.Rollback();
        throw;
    }
}

// ❌ 間違い（複数集約を1つのトランザクションで）
public async Task SaveMultipleAsync(Employee emp1, Employee emp2)
{
    using var transaction = _connection.BeginTransaction();
    await SaveAsync(emp1, transaction);  // 集約1
    await SaveAsync(emp2, transaction);  // 集約2（混在）
}
```

## 4. 集約の粒度決定

### 単一テーブル集約

```csharp
// 単純なビジネスオブジェクト
public sealed class Department : AggregateRoot<DepartmentRowId>
{
    private string _name;
    private ManagerEmployeeRowId _manager;  // オプション型RowId
    
    // m_departments テーブル のみ
}
```

**特徴：**
- 1つのテーブルのみ
- 変更が 1テーブルに限定
- 楽観ロック管理が簡単

---

### 複数テーブル集約（推奨）

**複数テーブルから構成される場合、複数 Entity で設計する。**

#### **1:1 関係テーブル**

```csharp
public sealed class Employee : AggregateRoot<EmployeeRowId>
{
    // 【1:1】Person を子Entity として直接内包
    public Person Person { get; private set; }
    
    // m_employees テーブル（親）
    // m_persons テーブル（子、1:1関係、FK在来）
}

public sealed class Person : Entity<PersonRowId>
{
    // PersonRowId のみを持つ
    // Parent（Employee）への参照は持たない
    // Mapper で「Employee.Person へ直接内包」で関係を表現
}
```

**特徴：**
- 子Entity が独立した RowId を持つ
- Parent への参照は DB の FK のみ
- 1:1 だから「常に存在」と仮定可能

---

#### **1:N 関係テーブル**

```csharp
public sealed class Employee : AggregateRoot<EmployeeRowId>
{
    // 【1:N】複数の子Entity
    public IReadOnlyCollection<DepartmentMembership> DepartmentMemberships 
        => _departmentMemberships.AsReadOnly();
    
    private readonly List<DepartmentMembership> _departmentMemberships;
    
    // m_employees テーブル（親）
    // m_department_memberships テーブル（複数行子、1:N関係）
}

public sealed class DepartmentMembership : Entity<DepartmentMembershipRowId>
{
    // 【重要】Parent への参照を明示的に保持
    public EmployeeRowId EmployeeRowId { get; private set; }
    
    public DepartmentRowId DepartmentRowId { get; private set; }
    public IsPrimary IsPrimary { get; private set; }
    public EndOn EndOn { get; private set; }
}
```

**特徴：**
- 各子Entity が 親RowId を参照
- Repository で parent RowId でフェッチ
- 複数行だから「変数個」と想定

---

### 複数テーブル集約の設計判断フロー

```
複数テーブルが必要か？
  ↓ Yes
テーブル間の関係は？
  ├─ 【1:1関係】
  │  └─ 子Entity が RowId のみを持つ
  │     （Parent への参照は持たない）
  │
  └─ 【1:N関係】
     └─ 各子Entity が ParentRowId を参照
        （Repository で親RowId でフェッチ）
```

## 5. 複数テーブル集約の設計

### 実装パターン（Employee 集約）

```
【テーブル構成】
m_employees            m_persons         m_department_memberships
├─ row_id (PK)    ├─ row_id (PK)    ├─ row_id (PK)
├─ biz_division   ├─ employee_row_id (FK) ├─ employee_row_id (FK)
├─ biz_id         │   ↓             ├─ department_row_id
├─ biz_code       └─ last_name      └─ is_primary
├─ retired_on         first_name       end_on
└─ ...                ...

【ドメイン設計】
Employee (集約根)
  ├─ Person (子Entity, 1:1)
  └─ DepartmentMembership[] (子Entity, 1:N)
```

### メリット

✅ **変更粒度が分離される**
- Person 変更 = m_persons のみ UPDATE
- DepartmentMembership 変更 = m_department_memberships のみ UPDATE

✅ **楽観ロックを独立管理**
- m_persons.row_version（Person の変更を検出）
- m_department_memberships.row_version（各 DepartmentMembership の変更を検出）

✅ **ドメインイベントが細粒度**
- EmployeeRetiredEvent（Employee の変更）
- PersonNameUpdatedEvent（Person の変更）
- DepartmentMembershipAddedEvent（新しい配属）

✅ **権限管理が柔軟**
- 個人情報編集と部署配置を別権限で管理可能

## 6. 集約間の通信

### ドメインイベント（非同期）

```csharp
// 集約内で変更発行
public void RetireEmployee(LocalDateTime retiredOn)
{
    RetiredOn = RetiredOn.From(retiredOn);
    
    RaiseDomainEvent(new EmployeeRetiredEvent(
        this.RowId,  // 誰が変更されたか
        retiredOn
    ));
}

// Application層でイベント処理（他の集約に影響）
public class EmployeeRetiredEventHandler : IDomainEventHandler<EmployeeRetiredEvent>
{
    public async Task Handle(EmployeeRetiredEvent @event)
    {
        // 別の集約（Insurance 等）への処理
    }
}
```

### Query Service パターン（同期）

複数の Context が別の Context のドメインモデル情報を **リアルタイムに読み取る** 場合：

```csharp
// 【汎用Application層】Query Service インターフェース
public interface IQueryService<TAggregate, TId> 
    where TAggregate : IAggregateRoot
{
    Task<TAggregate?> GetByIdAsync(TId id);
}

// 【Employee Context】実装
public class EmployeeQueryService : IQueryService<Employee, EmployeeRowId>
{
    private readonly IEmployeeRepository _repository;
    
    public async Task<Employee?> GetByIdAsync(EmployeeRowId id)
    {
        return await _repository.GetByIdAsync(id);
    }
}

// 【別の Context】使用例
public class TransferInsuranceUseCase
{
    private readonly IQueryService<Employee, EmployeeRowId> _employeeQuery;
    
    public async Task Execute(EmployeeRowId employeeId, InsuranceRequest request)
    {
        var employee = await _employeeQuery.GetByIdAsync(employeeId);
        if (employee == null)
            throw new EmployeeNotFoundException();
        
        // 従業員情報を使って保険配置
        await _repository.SaveAsync(new InsuranceProfile(employee, request));
    }
}
```

**メリット：**
- Context 間の結合度が低い
- ジェネリック定義で スケーラブル
- DDD の スコープ外（Aggregate 横断）を型で明示

## 7. よくある設計ミス

### ❌ ミス1：複数集約を1つの Repository で管理

```csharp
// ❌ 禁止
public class EmployeeAndInsuranceRepository
{
    public async Task SaveAsync(Employee emp, Insurance insurance)
    {
        // 2つの集約を混在（トランザクション境界が曖昧）
    }
}

// ✅ 正しい
public class EmployeeRepository
{
    public async Task SaveAsync(Employee emp) { ... }
}

public class InsuranceRepository
{
    public async Task SaveAsync(Insurance insurance) { ... }
}
```

### ❌ ミス2：子Entity から直接 Repository にアクセス

```csharp
// ❌ 禁止
public class Person : Entity<PersonRowId>
{
    public void Update(PersonRepository repo)
    {
        // 子Entity が直接 Repository にアクセス（集約境界の違反）
        repo.SaveAsync(this);
    }
}

// ✅ 正しい
public class Employee : AggregateRoot<EmployeeRowId>
{
    public Person Person { get; private set; }
    
    public void UpdatePersonName(LastName lastName)
    {
        Person.UpdateLastName(lastName);
        // Repository は集約根経由でのみ
    }
}
```

### ❌ ミス3：1:N 子Entity が Parent への参照を持たない

```csharp
// ❌ 禁止（Repository でどの Employee に所属するか分からない）
public sealed class DepartmentMembership : Entity<DepartmentMembershipRowId>
{
    // Parent（Employee）への参照がない
    public DepartmentRowId DepartmentRowId { get; private set; }
    public EndOn EndOn { get; private set; }
}

// ✅ 正しい
public sealed class DepartmentMembership : Entity<DepartmentMembershipRowId>
{
    public EmployeeRowId EmployeeRowId { get; private set; }  // ← Parent参照
    public DepartmentRowId DepartmentRowId { get; private set; }
    public EndOn EndOn { get; private set; }
}
```
