## 廃版理由

複数に分散していた null 処理に関するドキュメント（戦略、詳細設計）を、以下の理由から統一しました：

1. **理論的完全性**: Option/Maybe パターンとの関連性を明記
2. **表現統一**: IsSet / HasUpdated / IsDeleted の別名関係を統一
3. **レイヤ別責務**: Domain / Application / Infrastructure / DB の責務を明確化
4. **実装ガイド**: チェックリスト、テンプレート、よくあるエラーをワンストップで提供
