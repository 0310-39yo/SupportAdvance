# トランザクション分離レベル・業務排他制御方針

**プロジェクト:** SupportAdvance
**レイヤ:** Infrastructure
**対象:** DQL（照会系）の分離レベル方針、DML（更新系）の業務排他制御（チェックアウト方式）
**DB ORM:** 照会系 = Dapper / 更新系 = RepoDb
**版:** 1.0 / 2026-07-28

---

## 1. 位置づけ

本書は、SupportAdvance における **DB トランザクション分離レベルの使い分け**と、**基幹業務特有の長時間占有（人手作業・長時間バッチ）に対する排他制御**の方針を定める。

背景として、本プロジェクトの更新系業務には以下の特性がある。

- 製作単位（部品表等の「塊」）を複数部署が**段階的に**処理する（仕分 → 予算入力 → 発注 → 伝票発行）
- 各段階の処理は**人手で数時間〜数日**、または**再帰的な部品表展開・負荷計算等のプログラムで長時間**かかる場合がある
- 処理中は当該の塊を**他部署から触られたくない**が、**誰が処理中かは可視化**したい

> **📌 原則**
> 「長時間の排他」は DB トランザクション（分離レベル）では解決しない。DB トランザクションは常に短時間（ミリ秒〜秒オーダー）に留め、長時間の占有は**業務レベルのステータス・ロック列**で表現する。

## 2. DQL（照会系）の分離レベル方針

### 2.1 分類と分離レベルの選択基準

| 分類 | 分離レベル | 適用対象 | 例 |
|---|---|---|---|
| **マスター照会** | `ReadCommitted` | 単一テーブル参照、関連性の低い複数テーブル参照。スナップショット一貫性が不要なもの全般 | 参照マスタ取得、設定値参照 |
| **トランザクション照査** | `Snapshot` | 複数テーブルの状態が「同一時点」で一致している必要がある照査 | Car + Preferences の整合確認 |
| **占有状況のみ参照** | `ReadCommitted` | ブロック（塊）の占有者・開始時刻・ステータスのみを参照。ブロック本体の内容は不要 | 「このブロック誰が処理中？」という確認 |
| **ブロック詳細 + 占有情報参照** | `Snapshot` | ブロック本体の内容と占有情報を同時参照し、**一貫性が要件** | 「このブロックの仕分内容と、誰が処理中かを同時確認」 |
| **占有状況一覧表示** | `ReadCommitted` | 全ブロックの占有状況（Status / LockedBy / LockedAt）を一覧表示。古い情報も許容 | 管理画面での占有一覧、ダッシュボード |

### 2.2 設計判断

- **マスター照会・占有状況参照は `ReadCommitted` が既定**
  - 読み込み専用のため Dirty Read は防止され、Non-Repeatable/Phantom Read は実害にならない
  - リソース効率が最良

- **ブロック詳細 + 占有情報参照は `Snapshot`**
  - ブロックの「仕分状態」と「占有者」が「同一時点」で一致している必要がある
  - 例：仕分済みだと判定してから予算入力画面を開く際に、その間に占有者が変わっていると混乱する
  - DML 側の長時間占有中でも、Snapshot によりロック待機なしで読み込める

- `Snapshot` は tempdb の行バージョン管理を使用するため、**tempdb 容量を現行比 2〜3 倍確保**し、使用量を監視する

```sql
-- tempdb 使用量監視
SELECT SUM(reserved_page_count * 8 / 1024) AS tempdb_MB
FROM sys.dm_db_session_space_usage
WHERE session_id > 50;
```

### 2.3 Repository メソッド設計指針

分離レベルを Repository の**メソッド単位**で決める。呼び出し側（Application 層）は分離レベルを意識しない。

```csharp
// Infrastructure/Repository/IAssemblyBlockRepository.cs
public interface IAssemblyBlockRepository
{
    // パターン1: 占有状況のみ（ReadCommitted内部）
    Task<LockStatusDto> GetLockStatusAsync(BlockId id);

    // パターン2: ブロック詳細 + 占有情報（Snapshot内部）
    Task<BlockDetailWithLockDto> GetBlockDetailWithLockAsync(BlockId id);

    // パターン3: 占有状況一覧（ReadCommitted内部）
    Task<IEnumerable<LockStatusSummaryDto>> GetAllLockStatusesAsync();
}
```

実装側は分離レベルを隠蔽し、メソッドの責務に応じて自動選択。呼び出し側は「何を取得したいのか」を述べるだけで、分離レベルは Repository が決める。

## 3. DML（更新系）の業務排他制御（チェックアウト方式）

### 3.1 基本方針

製作単位（塊）は **DB トランザクションではなく、業務ステータス + 占有者列** によって排他制御する。DB トランザクションは、ロック取得・解放・状態遷移などの**一瞬の操作**にのみ使用し、いずれも `ReadCommitted` で完結する。

### 3.2 状態遷移

```
未着手 ─┬─→ 作業中 ─┬─→ 完了（次工程へ）
        │           │
        │           ├─→ 中断中（本人専用ロック保持）
        │           │        │
        │           │        ├─→ 作業中（本人が再開）
        │           │        │
        │           │        └─→ 強制解放済（管理者操作）
        │           │                 │
        │           │                 └─→ 作業中（引き継ぎ者が Take Over）
        └───────────┘
```

- 占有の粒度は**製作単位（あらかじめ決められた塊の単位）**で固定する。部品表内の一部品などの細粒度は対象外。
- 占有者（`LockedBy`）は人・長時間プログラムの両方を区別なく扱う（例: `USER:tanaka`、`BATCH:BOM展開_Job#12345`）。

### 3.3 テーブル設計

```sql
-- 製作単位（塊）テーブル
AssemblyBlocks (
    Id          ...,
    Status      NVARCHAR(20)      NOT NULL,  -- 未着手/作業中/中断中/強制解放済/仕分済/予算入力中/...
    LockedBy    NVARCHAR(50)      NULL,       -- 占有者（ユーザーID or プロセス名）
    LockedAt    DATETIME2         NULL,       -- 占有開始時刻
    LockToken   UNIQUEIDENTIFIER  NULL        -- 占有の正当性検証用トークン
)

-- 作業チェックポイント（中断時の途中経過退避）テーブル
WorkCheckpoints (
    Id              ...,
    BlockId         ...,
    LockToken       UNIQUEIDENTIFIER NULL,    -- 中断時点のトークン（強制解放後は NULL 許容で検索）
    CheckpointData  NVARCHAR(MAX)    NOT NULL, -- 途中経過（人手入力の下書き、または長時間処理の再開情報）
    SavedAt         DATETIME2        NOT NULL,
    SavedBy         NVARCHAR(50)     NOT NULL
)

-- 強制解放履歴（監査）テーブル
LockForceReleaseHistory (
    Id                ...,
    BlockId           ...,
    OriginalLockedBy  NVARCHAR(50)  NOT NULL, -- 解放された本来の占有者
    ReleasedBy        NVARCHAR(50)  NOT NULL, -- 実行した管理者
    ReleasedAt        DATETIME2     NOT NULL,
    Reason            NVARCHAR(200) NOT NULL  -- 解放理由（長期不在の説明等）
)
```

### 3.4 ロック取得（占有開始）

条件付き `UPDATE` の影響行数で競合を判定する。1件更新できれば取得成功、0件なら他者が既に占有中。

```csharp
// 設計例：ReadCommitted の単発 UPDATE で占有を取得する
var token = Guid.NewGuid();
var rows = await connection.ExecuteAsync(
    "UPDATE AssemblyBlocks SET Status = @Status, LockedBy = @User, LockedAt = @Now, LockToken = @Token " +
    "WHERE Id = @Id AND LockedBy IS NULL",
    new { Status = "作業中", User = actor, Now = clock.JstNow, Token = token, Id = id.Value });

if (rows == 0)
{
    // 取得失敗：占有中の使用者・開始時刻を提示する
    var current = await GetLockStatusAsync(id);
    throw new BlockLockedException(current.LockedBy, current.LockedAt);
}
```

### 3.5 アクセス試行時の可視化

他部署が占有中の塊にアクセスしようとした場合、占有者・開始時刻を提示する。単純 `SELECT`（`ReadCommitted`）で完結する。

```csharp
// 設計例：占有状況の提示
// 例外メッセージ: "tanaka さんが 10:23 から作業中です"
```

### 3.6 中断・再開

- 中断中も `LockedBy` は保持する（**本人専用**）。他者は占有状況を見られるが、取得も再開もできない。
- 途中経過は `WorkCheckpoints` に退避する（人手入力の下書き、または長時間処理の再開ポイント情報）。

```csharp
// 設計例：中断（途中経過の退避）
await connection.ExecuteAsync(
    "UPDATE AssemblyBlocks SET Status = @Status WHERE Id = @Id AND LockToken = @Token",
    new { Status = "中断中", Id = id.Value, Token = token });

await connection.ExecuteAsync(
    "INSERT INTO WorkCheckpoints (BlockId, LockToken, CheckpointData, SavedAt, SavedBy) " +
    "VALUES (@BlockId, @Token, @Data, @Now, @User)",
    new { BlockId = id.Value, Token = token, Data = checkpointJson, Now = clock.JstNow, User = actor });
```

```csharp
// 設計例：再開（本人確認 + チェックポイント読み出し）
var current = await GetLockStatusAsync(id);
if (current.LockedBy != actor)
    throw new AccessDeniedException(current.LockedBy, current.LockedAt);

var checkpoint = await connection.QuerySingleOrDefaultAsync<CheckpointDto>(
    "SELECT TOP 1 * FROM WorkCheckpoints WHERE BlockId = @Id ORDER BY SavedAt DESC",
    new { Id = id.Value });

await connection.ExecuteAsync(
    "UPDATE AssemblyBlocks SET Status = @Status WHERE Id = @Id",
    new { Status = "作業中", Id = id.Value });
```

### 3.7 強制解放（長期不在対応）

- **トリガー**: 管理者による明示的操作のみ。自動タイムアウトによる解放は行わない（作業途中データを勝手に失わせないため）。
- **チェックポイントの扱い**: 破棄せず保持する。引き継いだ担当者が途中経過から再開できるようにする。
- **解放後の状態**: `強制解放済` とし、以後は元の本人限定ではなく、権限を持つ任意の担当者が Take Over できる。
- **監査**: 元の占有者・実行した管理者・実行時刻・理由を `LockForceReleaseHistory` に必ず記録する。

```csharp
// 設計例：強制解放
var current = await GetLockStatusAsync(id);
if (current.LockedBy is null)
    throw new InvalidOperationException("占有されていません");

await connection.ExecuteAsync(
    "UPDATE AssemblyBlocks SET Status = @Status, LockedBy = NULL, LockToken = NULL WHERE Id = @Id",
    new { Status = "強制解放済", Id = id.Value });

await connection.ExecuteAsync(
    "INSERT INTO LockForceReleaseHistory (BlockId, OriginalLockedBy, ReleasedBy, ReleasedAt, Reason) " +
    "VALUES (@BlockId, @Original, @Admin, @Now, @Reason)",
    new { BlockId = id.Value, Original = current.LockedBy, Admin = adminActor, Now = clock.JstNow, Reason = reason });
```

```csharp
// 設計例：強制解放後の引き継ぎ（Take Over）
// LockToken は再発行し、直近のチェックポイントを BlockId のみで検索して引き継ぐ
var checkpoint = await connection.QuerySingleOrDefaultAsync<CheckpointDto>(
    "SELECT TOP 1 * FROM WorkCheckpoints WHERE BlockId = @Id ORDER BY SavedAt DESC",
    new { Id = id.Value });

var newToken = Guid.NewGuid();
await connection.ExecuteAsync(
    "UPDATE AssemblyBlocks SET Status = @Status, LockedBy = @User, LockedAt = @Now, LockToken = @Token " +
    "WHERE Id = @Id AND Status = '強制解放済'",
    new { Status = "作業中", User = newActor, Now = clock.JstNow, Token = newToken, Id = id.Value });
```

## 4. 設計制約・禁止事項

### 4.1 レイヤ制約（CLAUDE.md 準拠）

| ❌ 禁止 | ✅ 許可 |
|---|---|
| ❌ Domain/Application 層が Dapper/RepoDb の型・SQL を直接参照すること | ✅ Infrastructure 層の Repository がラップして提供すること |
| ❌ 占有状態を Application 層でのみ判定し DB 側で保証しないこと（レースコンディションの原因） | ✅ 占有取得は必ず DB 側の条件付き UPDATE（影響行数判定）で保証すること |

### 4.2 実装上の禁止事項

- **長時間 DB トランザクションの使用禁止**: 人手作業・長時間バッチの「処理中」を DB トランザクションで表現しない（ロック肥大化・デッドロック・tempdb/ログ肥大化の原因になるため）。
- **自動タイムアウトによる強制解放の禁止**: 長期不在への対応は必ず管理者の明示操作を介する（無人での強制解放はデータ破損・二重作業のリスクがあるため）。
- **チェックポイントの無断破棄禁止**: 中断・強制解放のいずれにおいても、途中経過データは明示的な完了・破棄操作がない限り保持する。

### 4.3 占有中の照会ポリシー（透視化）

**基本方針: 占有中のブロックは、占有者以外も自由に読める。**

- **読み込み権限**: 誰でも何度でも読み込み可能。占有状態は制限しない。
- **意図**: 各部署が「進捗状況」を可視化でき、業務の透明性が保たれる。
- **制限対象**: 読み込みではなく、「**書き込み（UPDATE / DELETE）は占有中は不可**」という設計（業務排他）

**実装上の留意:**

- 占有中のブロック詳細を読む場合、`GetBlockDetailWithLockAsync` で `Snapshot` 分離レベルを使用し、ブロック本体と占有情報の整合性を保証する。
- 占有情報だけを読む場合（進捗確認）、`GetLockStatusAsync` で `ReadCommitted` を使用し、軽量な照査を実現。
- UI では占有情報を常に表示（例：「tanaka さんが 10:23 から作業中」）し、他ユーザーが作業状況を把握できるようにする。

**例外的な秘匿要件がある場合:**
- 業務的に「占有中は内容を秘匿する」という要件が発生した場合、その旨を明記し、Repository に秘匿用メソッドを追加する（本書のスコープ外）。

## 5. 実装ガイドライン

### 5.1 実装義務

- 占有取得・解放・状態遷移の Repository メソッドは、必ず単発の条件付き `UPDATE`（影響行数で成否判定）として実装し、複数ステートメントを1トランザクションに束ねない。
- 占有中の可視化用 `GetLockStatusAsync` は、状態遷移メソッドと同一 Repository に用意し、呼び出し側（Application 層）が占有チェックを怠らない構成にする。
- 強制解放は Application 層で管理者権限チェックを行った上で Infrastructure の `ForceReleaseAsync` を呼び出す（権限判定はドメイン/認可の責務であり、本書のスコープ外）。

### 5.2 DQL メソッド設計の実装例

占有情報を含む照会系は、**メソッド名で用途を明確にし、分離レベルは内部で選択する**。

```csharp
// Infrastructure/Persistence/AssemblyBlockRepository.cs
public class AssemblyBlockRepository : IAssemblyBlockRepository
{
    private readonly IDbConnectionFactory _connectionFactory;

    // パターン1: 占有状況のみ（ReadCommitted内部）
    public async Task<LockStatusDto> GetLockStatusAsync(BlockId id)
    {
        using var conn = _connectionFactory.CreateConnection();
        using var tx = conn.BeginTransaction(IsolationLevel.ReadCommitted);
        
        return await conn.QuerySingleOrDefaultAsync<LockStatusDto>(
            "SELECT Status, LockedBy, LockedAt FROM AssemblyBlocks WHERE Id = @Id",
            new { Id = id.Value },
            transaction: tx);
    }

    // パターン2: ブロック詳細 + 占有情報（Snapshot内部）
    // 「仕分状態」と「占有者」が同一時点で一致していることが重要
    public async Task<BlockDetailWithLockDto> GetBlockDetailWithLockAsync(BlockId id)
    {
        using var conn = _connectionFactory.CreateConnection();
        using var tx = conn.BeginTransaction(IsolationLevel.Snapshot);  // ← Snapshot を明示
        
        var block = await conn.QuerySingleAsync<BlockDetailDto>(
            "SELECT Id, Title, Content, Status, LockedBy, LockedAt FROM AssemblyBlocks WHERE Id = @Id",
            new { Id = id.Value },
            transaction: tx);

        return new BlockDetailWithLockDto(
            Id: block.Id,
            Title: block.Title,
            Content: block.Content,
            Status: block.Status,
            LockedBy: block.LockedBy,
            LockedAt: block.LockedAt);
    }

    // パターン3: 占有状況一覧（ReadCommitted内部）
    public async Task<IEnumerable<LockStatusSummaryDto>> GetAllLockStatusesAsync()
    {
        using var conn = _connectionFactory.CreateConnection();
        using var tx = conn.BeginTransaction(IsolationLevel.ReadCommitted);
        
        return await conn.QueryAsync<LockStatusSummaryDto>(
            "SELECT Id, Status, LockedBy, LockedAt FROM AssemblyBlocks ORDER BY LockedAt DESC",
            transaction: tx);
    }
}
```

### 5.3 RepoDb / Dapper の使い分け

| 用途 | ライブラリ | 分離レベル |
|---|---|---|
| 照会系（DQL） | Dapper | `ReadCommitted` または `Snapshot`（2.1章参照） |
| 更新系（DML・占有制御） | RepoDb | `ReadCommitted`（単発操作のみ） |

### 5.4 Presentation 層での参照例

Application 層が Repository 経由で取得した DTO を UI に表示する際、分離レベルの選択はすべて Repository に委譲。

```csharp
// Application/UseCases/ViewBlockDetailUseCase.cs
public class ViewBlockDetailUseCase
{
    private readonly IAssemblyBlockRepository _repo;

    public async Task<BlockDetailVm> ExecuteAsync(BlockId id)
    {
        // Repository メソッドの責務で分離レベルが決まる
        // 呼び出し側は「詳細 + 占有情報が必要」という要件を述べるだけ
        var detail = await _repo.GetBlockDetailWithLockAsync(id);

        return new BlockDetailVm
        {
            Id = detail.Id,
            Title = detail.Title,
            Status = detail.Status,
            LockedBy = detail.LockedBy,
            LockedAt = detail.LockedAt,
            LockMessage = detail.LockedBy != null 
                ? $"{detail.LockedBy} さんが {detail.LockedAt:HH:mm} から作業中です"
                : "未着手"
        };
    }
}
```

## 6. 占有監視・管理機能

### 6.1 長期占有の検知基準

基幹システムとして、占有の長期化を監視し、強制解放の対象候補を検出する仕組みが必須。

| 占有期間 | 判定 | 対応 |
|---|---|---|
| 0 ～ 24 時間 | 正常 | 通常処理 |
| 24 ～ 48 時間 | 警告 | 管理画面でアラート表示。占有者への確認推奨 |
| 48 時間以上 | 長期占有 | 強制解放の対象候補。管理者による確認・決定が必須 |

> **📌 補足**
> 占有期間の基準は業務特性に応じて調整可能。例：再帰的な部品表展開など「実行に数時間かかるバッチ」は別途閾値を設定することも可能。

### 6.2 管理画面での可視化

占有監視ダッシュボードには以下を表示する。

- **長期占有ブロック一覧**
  - ブロック ID、占有者、占有開始時刻、占有期間
  - 警告・危険レベルで色分け表示
  
- **強制解放の対象候補**
  - 48 時間以上占有されているもの
  - 1クリックで詳細確認・強制解放操作に遷移できるUIを用意

### 6.3 Repository メソッド設計

```csharp
// Infrastructure/Repository/IAssemblyBlockRepository.cs
public interface IAssemblyBlockRepository
{
    // 既存メソッド...

    // 新規: 長期占有の検知
    
    /// <summary>
    /// 指定時間以上占有されているブロックを取得
    /// </summary>
    /// <param name="threshold">閾値（例：TimeSpan.FromHours(24)）</param>
    Task<IEnumerable<LongLockAlertDto>> GetLongLockedBlocksAsync(TimeSpan threshold);

    /// <summary>
    /// 特定ブロックの占有期間を取得
    /// </summary>
    Task<LockDurationDto?> GetLockDurationAsync(BlockId id);

    /// <summary>
    /// 警告レベルの長期占有ブロック（24～48時間）を取得
    /// </summary>
    Task<IEnumerable<LongLockAlertDto>> GetWarningLockBlocksAsync();

    /// <summary>
    /// 危険レベルの長期占有ブロック（48時間以上）を取得
    /// </summary>
    Task<IEnumerable<LongLockAlertDto>> GetCriticalLockBlocksAsync();
}
```

### 6.4 実装例

```csharp
// Infrastructure/Persistence/AssemblyBlockRepository.cs
public class AssemblyBlockRepository : IAssemblyBlockRepository
{
    private readonly IDbConnectionFactory _connectionFactory;
    private readonly IClock _clock;

    /// <summary>
    /// 指定時間以上占有されているブロックを取得
    /// </summary>
    public async Task<IEnumerable<LongLockAlertDto>> GetLongLockedBlocksAsync(TimeSpan threshold)
    {
        using var conn = _connectionFactory.CreateConnection();
        using var tx = conn.BeginTransaction(IsolationLevel.ReadCommitted);

        return await conn.QueryAsync<LongLockAlertDto>(@"
            SELECT 
                Id, 
                Status,
                LockedBy, 
                LockedAt,
                DATEDIFF(HOUR, LockedAt, @Now) AS LockedHours,
                CASE 
                    WHEN DATEDIFF(HOUR, LockedAt, @Now) >= 48 THEN 'Critical'
                    WHEN DATEDIFF(HOUR, LockedAt, @Now) >= 24 THEN 'Warning'
                    ELSE 'Normal'
                END AS AlertLevel
            FROM AssemblyBlocks
            WHERE LockedBy IS NOT NULL 
                AND DATEDIFF(HOUR, LockedAt, @Now) > @ThresholdHours
            ORDER BY LockedAt ASC",
            new { Now = _clock.JstNow, ThresholdHours = (int)threshold.TotalHours },
            transaction: tx);
    }

    /// <summary>
    /// 特定ブロックの占有期間を取得
    /// </summary>
    public async Task<LockDurationDto?> GetLockDurationAsync(BlockId id)
    {
        using var conn = _connectionFactory.CreateConnection();
        using var tx = conn.BeginTransaction(IsolationLevel.ReadCommitted);

        return await conn.QuerySingleOrDefaultAsync<LockDurationDto>(@"
            SELECT 
                Id,
                LockedBy,
                LockedAt,
                DATEDIFF(HOUR, LockedAt, @Now) AS LockedHours,
                CASE 
                    WHEN DATEDIFF(HOUR, LockedAt, @Now) >= 48 THEN 'Critical'
                    WHEN DATEDIFF(HOUR, LockedAt, @Now) >= 24 THEN 'Warning'
                    ELSE 'Normal'
                END AS AlertLevel
            FROM AssemblyBlocks
            WHERE Id = @Id",
            new { Id = id.Value, Now = _clock.JstNow },
            transaction: tx);
    }

    /// <summary>
    /// 警告レベル（24～48時間）の長期占有ブロックを取得
    /// </summary>
    public async Task<IEnumerable<LongLockAlertDto>> GetWarningLockBlocksAsync()
    {
        return await GetLongLockedBlocksAsync(TimeSpan.FromHours(24));
    }

    /// <summary>
    /// 危険レベル（48時間以上）の長期占有ブロックを取得
    /// </summary>
    public async Task<IEnumerable<LongLockAlertDto>> GetCriticalLockBlocksAsync()
    {
        return await GetLongLockedBlocksAsync(TimeSpan.FromHours(48));
    }
}
```

```csharp
// Application/UseCases/MonitorLongLocksUseCase.cs
public class MonitorLongLocksUseCase
{
    private readonly IAssemblyBlockRepository _repo;

    /// <summary>
    /// 監視ダッシュボード用：全長期占有ブロックを取得
    /// </summary>
    public async Task<LockMonitoringVm> ExecuteAsync()
    {
        var critical = await _repo.GetCriticalLockBlocksAsync();  // 48h以上
        var warning = await _repo.GetWarningLockBlocksAsync();     // 24～48h

        return new LockMonitoringVm
        {
            CriticalBlocks = critical.ToList(),
            WarningBlocks = warning.ToList(),
            TotalCritical = critical.Count(),
            TotalWarning = warning.Count(),
            LastUpdated = DateTime.Now
        };
    }
}
```
