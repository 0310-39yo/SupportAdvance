## 修正手法

### 仕様書修正ステップ

1. **グループをVO観点に対応付け**
   ```
   グループ 1: 生成メソッド（Create）
        ↓
   VO-CONS: コンストラクタ・生成
   ```

2. **テストコードを確認**
   - テストファイル内のメソッド名を把握
   - テスト実装列に記載

3. **観点IDテーブルを作成**
   ```markdown
   | 観点ID | 観点（説明） | 分類 | テスト実装 |
   |--------|------|------|-----------|
   | VO-CONS-01 | ... | 正常系 | ✅/⚠️/❌ |
   ```

4. **テスト実装状況を分類**
   - ✅: テスト実装済み（ファイル::メソッド名 記載）
   - ⚠️: 部分実装または手動確認
   - ❌: 未実装（実装待ちまたは要検討）

---

## 観点ID体系（Entity向け標準パターン）

```
VO-CONS-xx  : コンストラクタ・生成（Create, Reconstruct）
VO-PROP-xx  : プロパティアクセス（値取得、読み取り専用確認）
VO-METHOD-xx: ドメインメソッド（IsActive, Retire等のビジネスロジック）
VO-EQ-xx    : Equals等価判定（同じ ID で等価）
VO-NE-xx    : Equals非等価判定（異なる ID で非等価）
VO-HC-xx    : GetHashCode（ハッシュ整合性）
VO-VALID-xx : 値検証（無効な入力で例外発生）
VO-INTEG-xx : 統合テスト（複数プロパティの整合性）
VO-EVNT-xx  : ドメインイベント（イベント発行確認）
```

## 実装への提案

### 優先順位

**高:**
- VO-CONS: Create/Reconstruct メソッドのテスト（ビジネス生成の核）
- VO-METHOD: IsActive 等のビジネスロジック検証
- VO-PROP: プロパティ読み取り専用確認（不変性が重要）

**中:**
- VO-EQ/NE/HC: Entity<TId> の等価性実装が正しいか確認（Entity の基本）
- VO-INTEG: 複数プロパティの整合性確認

**低:**
- VO-VALID: ValueObject の検証に依存（ValueObject テストで検証済み）
