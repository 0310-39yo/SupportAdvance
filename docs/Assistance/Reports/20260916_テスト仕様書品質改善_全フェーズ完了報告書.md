## 🔄 VO-形式の標準化完成

### 確立した観点ID体系

**Entity層向け:**
```
VO-CONS-xx  : コンストラクタ・生成
VO-PROP-xx  : プロパティアクセス
VO-METHOD-xx: ドメインメソッド（IsActive等）
VO-EQ/NE-xx : 等価性判定
VO-HC-xx    : GetHashCode
VO-VALID-xx : 値検証
VO-INTEG-xx : 統合テスト
VO-EVNT-xx  : ドメインイベント
```

**Application層向け:**
```
VO-EXEC-xx  : UseCase実行
VO-RESULT-xx: 戻り値
VO-ERROR-xx : 異常系
VO-STATE-xx : 状態変化
VO-SIDE-xx  : 副作用
VO-QUERY-xx : Query Service
```

**Infrastructure層向け:**
```
VO-MAP-xx   : マッピング（Entity ↔ DbModel）
VO-TYPE-xx  : 型変換・null処理
VO-CRUD-xx  : CRUD操作（Save/Get/Update/Delete）
VO-AUDIT-xx : 監査フィールド自動設定
VO-HASH-xx  : ハッシュ生成・検証
VO-SECURITY-xx: セキュリティ検証
VO-TXRX-xx  : トランザクション・例外処理
VO-INTEG-xx : ラウンドトリップテスト
```

## 📋 テスト実装状況の記載方法

すべての観点に以下の3段階を記載：

| 状態 | 記号 | 意味 |
|------|------|------|
| **実装済み** | ✅ | テストファイル::メソッド名 記載例: `EmployeeTests.cs::TestCreate01` |
| **部分実装** | ⚠️ | 手動確認など条件付き |
| **Skip/未実装** | ❌ / ⏸️ | 未実装理由を記載（DB接続必須、実装待ち等） |
