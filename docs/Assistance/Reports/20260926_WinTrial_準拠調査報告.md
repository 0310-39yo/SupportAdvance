# WinTrial 準拠調査報告

調査日: 2026-09-26
対象: `src/Presentation/WinTrial`（Program.cs、DependencyInjection.cs、Services、ViewModels、Views）
観点: MVVM／MVVM Toolkit／クリーンアーキテクチャ／プロジェクトの基本方針（WpfTrial 調査・修正と同じ観点）
方法: 全ファイルの静的な読解。実行・画面確認は未実施（ログインに DB が必要なため）。Designer ファイルは Designer.cs のうち関連箇所のみ確認

## 1. 総評

- 依存方向（Presentation → Infrastructure は Composition Root のみ）は Phase 3・4 の対応で準拠し、自動検証も入っている
- 一方で **ViewModel／画面の重複**、**未使用コード**、**WpfTrial で修正済みの問題の残存** が目立つ
- WinForms は WPF と違い XAML のデータテンプレートやコマンドバインディングが無く、バインディングはコードビハインドで配線する。その配線自体は「View の責務」に収まっており、MVVM の観点では許容範囲

## 2. 準拠できている点

- ViewModel（`Form1ViewModel`、`LoginDialogViewModel`）は `System.Windows.Forms`／Syncfusion／`Views` に依存していない（using を確認）
- MVVM Toolkit（`ObservableObject`、`[RelayCommand]`、`[ObservableProperty]`）を採用し、View は `Button.Command` と `DataBindings` でバインドしている
- `LoginDialog` は ViewModel がダイアログを知らず、イベント経由で View が `DialogResult` を確定する設計で、WpfTrial と同等
- Presentation → Infrastructure の参照は `Program.cs` のみ（`PresentationArchitectureTests` で常時検証）
- `BusinessDayClockViewModel`（Shared）を共通利用している

## 3. 指摘事項

### 重大度: 高

**W-1. ViewModel の重複（WpfTrial との二重管理）**
- [Form1ViewModel.cs](../../../src/Presentation/WinTrial/ViewModels/Form1ViewModel.cs) は WpfTrial の修正前（Phase 1 以前）とほぼ同一。[LoginDialogViewModel.cs](../../../src/Presentation/WinTrial/ViewModels/LoginDialogViewModel.cs) も `LoginWindowViewModel` の名前違いのコピー
- 両方とも UI 型に依存しないため、`Presentation.Shared` に共通化できる（Shared は既に Application／Common／Crosscutting を参照可能）
- 現状は WpfTrial 側だけ単体テストがあり、修正も WpfTrial だけに反映されている

**W-2. WpfTrial で修正済みの問題が WinTrial に残っている**
- `Form1ViewModel`: `(AppSettings)appSettings` のダウンキャスト（未使用フィールド）、「見つかりません」「空入力」「数値以外」時に `DepartmentNames` が前回値のまま、`catch → throw;`、空の `Dispose()`（`IDisposable` 未実装）
- `LoginDialogViewModel`: 予期しない例外で `ex.Message` を画面表示し `LogWarning`（内部情報の漏洩とログレベル不整合）

### 重大度: 中

**W-3. 未使用・未接続のコード**
- `Form1View` は DI 登録されているが、`Program.cs` は `MainWindow` しか表示しない。どこからも生成されない（`Form1ViewModel` とその BusinessDayClock パネルも到達不能）
- `MainWindowViewModel` は空クラスで、DI 登録も利用もない。XML コメントが無く CS1591 警告が出ている
- `MainWindow` は ViewModel を持たず、`MainWindow_Load` は空

**W-4. エラーラベル表示の配線が誤りの可能性（要実機確認）**
- [LoginDialog.cs:60](../../../src/Presentation/WinTrial/Views/LoginDialog.cs:60) は `lblError.Visible` に文字列プロパティ `ErrorMessage` を直接バインドしている（`nullValue` は `""`）
- 文字列から bool への変換は "True"／"False" 以外で失敗する。バインディング失敗は例外にならず黙って無視されるため、エラー表示の可視制御が意図通り動いていない可能性が高い
- WpfTrial の `StringEmptyToVisibilityConverter` に相当する `Binding.Format` イベントでの変換が必要

**W-5. DI 登録が分散している**
- `Program.cs` が `LoginDialogViewModel`／`LoginDialog` を直接登録し、それ以外は `AddWinTrialModules()`。WpfTrial は `AddWpfTrialModules()` に集約済み
- `GetRequiredService<MainWindow>(...) ?? ActivatorUtilities.CreateInstance<MainWindow>(...)` の `??` は到達しない（`GetRequiredService` は null を返さない）。`ServiceProviderServiceExtensions.GetService<>(host.Services)` と拡張メソッドを静的呼び出しの形で書いている点も不自然

### 重大度: 低

- `LoginDialogViewModel`: `IsNotLoading`（`Enabled` バインド用の反転プロパティ）。WinForms には Converter が無いため `Binding.Format` で反転すれば廃止可能（WpfTrial は Phase 5 で廃止済み）
- `[ObservableProperty]` のフィールド命名が `loginId` 形式（WpfTrial は Phase 5 で `_loginId` に統一済み）
- `Form1View`: `readonly` フィールドの `= null!` 初期化、`_appSettings?.` の不要な null 条件、動作確認用のログ（`"情報"`／`"警告"`）が残っている。View が `IAppLogging`／`IAppSettings` を直接受け取っている点も、ログ出力のためだけなら ViewModel 側に寄せるのが望ましい
- `MainWindow.cs`: 不要な `using` が多数、`SkinManager.SetVisualStyle(this, "Office2016DarkGray")`（WpfTrial は Office2019White、csproj は Office2019 テーマを参照。テーマが揃っていない）、旧スタイルの名前空間ブロック
- パスワードは `TextBox.PasswordChar` でマスクしているが、ViewModel 上は `string` のまま保持（WpfTrial と同じ設計上の制約）

## 4. 自動検証の状況

- 適用済み: WinTrial の Composition Root 以外が Infrastructure に依存しないこと（`PresentationArchitectureTests`）
- 未適用: WinTrial の ViewModel が `System.Windows.Forms`／Syncfusion／`Views` に依存しないこと。現状の ViewModel は違反していないため、規則を追加してもそのまま合格する見込み（今後の回帰防止）
- 単体テストは WinTrial 側に無い（W-1 の共通化で WpfTrial.Tests のテストが実質共有される）
