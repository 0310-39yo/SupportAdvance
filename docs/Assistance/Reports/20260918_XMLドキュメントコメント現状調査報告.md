## 3. 問題点

| # | 問題 | 影響 | 件数・場所 |
|---|---|---|---|
| 1 | **XML として壊れている**（`Entity<TId>` や ``` の中の `<…>`） | そのコメントが IntelliSense に**まったく表示されない** | 7 ブロック（`IQueryService.cs:5` など。詳しくはガイドの §8-1） |
| 2 | 【見出し】や箇条書きを `<summary>` の中に書いている | IntelliSense では改行が無視され、1 つの長い文として表示される | ほぼすべての型 |
| 3 | **コメントが実装と食い違っている** | 読んだ人が誤解する | `EmployeeRetiredEvent.cs:21` の `Division` に「部署コード」と書かれているが、実際に入るのは従業員種別区分（`TypeDivision.ToString()`） |
| 4 | 送出する例外が書かれていない | 呼び出す人が例外を処理し忘れる | `Employee.RetireEmployee`、`Employee.AddDepartmentMembership` など |
| 5 | `<param>` がない、または空 | シグネチャヘルプに引数の説明が表示されない | `Employee.RetireEmployee`、`RepositoryBase` の各メソッド、`PrimitiveValueObject.cs:19`（空） |
| 6 | プロパティやコンストラクターに `<returns>` を使っている | 正しくは `<value>`。コンストラクターには書かない | 9 か所（`UpdatedAt.Value`、`HasUpdated` など）、`UpdatedAt.cs:19` |
| 7 | 同じことを繰り返している（summary と【責務】が同じ文） | 情報が増えず、読むのに時間がかかるだけ | `UpdatedAt.Equals`／`GetHashCode` など、値オブジェクトの override |
| 8 | 型名を普通の文字列で書いている（`<see cref>` を使っていない） | 名前を変えたときにコメントだけ古い名前で残る | ほぼすべて |
| 9 | コードの例を Markdown の ``` で書いている | IntelliSense で読めず、問題 1 の原因にもなる | 3 ブロック |
| 10 | public なコンストラクター（DI 用）にコメントがない | CS1591 の対象になる。`ArgumentNullException` が書かれていない | `AuthenticateLocalUserUseCase`、`LoginWindowViewModel`、`EmployeeRetiredEvent` など |
| 11 | `[ObservableProperty]` を付けたフィールドにコメントがない | 生成されるプロパティ（画面にバインドする対象）の説明がない | `LoginWindowViewModel.cs:33-46` |
| 12 | 型そのものにコメントがない | | `IClock`、`AppSettings`、`AuthMethod` の各メンバー（11 件） |
| 13 | 文体が「〜する」「〜します」「体言止め」で混ざっている。「。」がある文とない文が混ざっている | 見た目がそろわない。**体言止めに統一し、「。」は文の区切りにだけ使い、最後の文には付けない**（ガイドの §4。既存コードの約 98% はすでに最後の句点なし） | 全体 |
| 14 | `GenerateDocumentationFile` が `SharedKernel` でしか有効になっていない | 問題 1・5・8 がビルドで検出されない | `SharedKernel.csproj` 以外のすべてのプロジェクト |

## 4. 今後の対応（案）

> **2026-09-18 追記**: 承認を得て、下表の「高」「中」はすべて実施済み。詳細は §5。

| 優先度 | 対応 | 規模 |
|---|---|---|
| 高 | 問題 1: 壊れている 7 ブロックを直す（IntelliSense に表示されるようになる） | 7 ファイル |
| 高 | 問題 3: `EmployeeRetiredEvent.Division` のコメントを直す | 1 行 |
| 中 | 問題 14: `src/Directory.Build.props` で `GenerateDocumentationFile` を有効にし、CS1570／CS1572／CS1573／CS1574／CS1734 をエラーにする（ガイドの §10） | 1 ファイル。問題 1 を直した後に行う |
| 中 | 問題 4・5: Domain の public メソッドに `<param>`／`<exception>` を書き足す | Domain 層 |
| 低 | 問題 2・6・7・8・13: ファイルを修正するときに、ガイドに合わせて直す（ボーイスカウトルール） | 随時 |
