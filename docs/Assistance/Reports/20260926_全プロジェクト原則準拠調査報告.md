## 3. ルール違反（軽微）

### 3-1. Application の DTO が `DateTime` を持つ

- `src/Contexts/Authentication/Authentication.Application/Dtos/AuthenticateLocalUserResponse.cs:34`
  `public DateTime LoggedInAt { get; init; }`
- CLAUDE.md: 「Application/DTO は LocalDateTime」
- UseCase 側（`AuthenticateLocalUserUseCase.cs:166`）は `now.Value` で `DateTime` に落としている。
- 対処案: 型を `LocalDateTime` に変更し、`.Value` を外す。利用側（Presentation）の影響を確認する。

### 3-2. `EmployeeMapper` が `IClock` を保持している

- `src/Contexts/Employee/Employee.Infrastructure/Mappers/EmployeeMapper.cs:23,30,100`
- CLAUDE.md: 「Mapper の Clock 依存を削除する（テスト容易性）」
- 用途は `Employee.Reconstruct(..., _clock, ...)` への受け渡し。ただし基底の `IEntityMapper.ToDomainEntity(dbModel, IClock clock)` は引数で Clock を受け取る設計で、CLAUDE.md の例示コードも同じ。**コンストラクターで保持する形だけが、責務分離表の記述と食い違っている。**
- 対処案: 引数の `clock` を使い、フィールドとコンストラクター引数を削除する。

## 4. 要判断（原則と設計ガイドの解釈差）

### 4-1. Domain エンティティの nullable プロパティ

「Domain 層 null 厳格性原則」（未設定は型で表現）に照らすと、次の 3 つが該当する。

| 箇所 | 型 |
|---|---|
| `UserAuthSession.LoggedOutAt`（:62）、`IsActive()` で `== null` 判定（:180） | `LocalDateTime?` |
| `UserAuthSession.LoginCredentialsRowId`（:71） | `LoginCredentialsRowId?` |
| `DepartmentMembership.DepartmentName` | `string?` |

いずれも「Unset() を持つ値オブジェクト」にする案が原則どおり。
`LoggedOutAt` は `UpdatedAt` と同じ Unset パターン（`HasLoggedOut` などの別名プロパティ）が適する。

### 4-2. Domain の値オブジェクトに `DateTime` が現れる

`TryFromDbValue(DateTime?)` / `ToDbValue()` が、`SharedKernel` の監査 VO（`CreatedAt`、`UpdatedAt`、`DeletedAt`）と、`Employee.Domain`・`Department.Domain` の日付 VO（`RetiredOn`、`EndOn`、`EffectiveAt`、`ExpirationOn`、`AbolishedOn`）にある。
「FromDbValue / ToDbValue パターンガイド」で定めた DB 境界メソッドであり、**設計上は許容範囲**と読めるが、CLAUDE.md の「Domain は DateTime の直接使用禁止」とは文言上ぶつかる。CLAUDE.md に例外の一文を足すか、ガイドとの整合を確認したい。

### 4-3. Composition Root の記述が `Program.cs` 固定

CLAUDE.md は「Infrastructure 参照は `Program.cs` のみ」と書くが、WpfTrial の Composition Root は `App.xaml.cs`（WPF の構造上、`Program.cs` がない）。
実態は原則の趣旨どおりで、`PresentationArchitectureTests` も通っている。**CLAUDE.md の文言を「Composition Root（`Program.cs` または `App.xaml.cs`）」に直す**のが妥当。
