### Phase B: 詳細調査（次段階）

#### B-1: 観点ID定義状況の確認

**対象:** Phase 3-2 以降の47仕様書

**確認項目:**
- [ ] 観点ID定義が存在するか（有/無）
- [ ] 観点ID形式が標準か（VO-xxx vs TC-xxx）
- [ ] 観点テーブルが完全か
- [ ] 観点名がビジネス意味を持つか

**実施方法:** 各ファイル読み込み、「テスト観点一覧」セクション確認

#### B-2: テストコード実装状況の確認

**対象:** Phase 3-2以降で観点ID定義がある仕様書

**確認項目:**
- [ ] 対応するテストファイルが存在するか
- [ ] 観点ID に対応するテストメソッドが実装されているか
- [ ] テストメソッド命名規則は統一されているか

**実施方法:** 
```bash
# テストファイルロケーション
docs/Contexts/Employee/Domain/ValueObjects/.../Xxx_単体テスト仕様書.md
  ↓
tests/Contexts/Employee.Domain.Tests/ValueObjects/.../XxxTests.cs
```

#### B-3: 不一致パターンの分類

実装時に遭遇する4つのパターン：

| パターン | 現象 | 対応 |
|---------|------|------|
| **A1** | 観点ID定義あり → テストコード完全実装 | ✅ OK（修正不要） |
| **A2** | 観点ID定義あり → テストコード部分実装 | ⚠️ 仕様書に「実装状況」追記 or テスト追加 |
| **A3** | 観点ID定義あり → テストコード未実装 | ❌ 仕様書削除 or テスト新規作成 |
| **B1** | 観点ID定義なし → テストコード実装あり | ❌ 仕様書に観点ID追記 |
| **B2** | 観点ID定義なし → テストコード未実装 | ❌ 仕様書全体見直し |

## 3. 修正計画フェーズ（B-3完了後）

### Phase C: パターン別修正実施

#### C-A: 観点IDあり → テスト実装ありの場合（A1パターン）

**作業:** なし（確認のみ）

**成果物:** 「✅ 対応完了」マーク

#### C-B: 観点IDあり → テスト部分実装の場合（A2パターン）

**判断基準:** 
- 重要な観点なのか？
- 実装コストは？

**対応案:**
1. **観点が重要 + 実装コスト小** → テストコード追加
2. **観点が重要 + 実装コスト大** → 仕様書に「実装待ち」と記載
3. **観点が重要でない** → 観点を仕様書から削除

#### C-C: 観点IDあり → テスト未実装の場合（A3パターン）

**対応:**
1. 仕様書から該当観点を削除、または
2. テストコードを新規作成

**優先度:** 観点の「重要度」と「実装コスト」で判定

#### C-D: 観点IDなし → テスト実装ありの場合（B1パターン）

**対応:** 仕様書に観点ID テーブルを追加

**実施内容:**
1. テストメソッド一覧を取得
2. 各テストメソッドから観点を推定
3. 観点ID（VO-GEN-01 等）を割り当て
4. テスト観点一覧テーブルに記載

## 4. 実装ガイドライン

### 実装順序

1. **Phase B-1**: 全仕様書の観点ID定義状況をスプレッドシート/表にまとめる
2. **Phase B-2**: テストコード実装状況を確認（ファイル存在 + メソッド数を確認）
3. **Phase B-3**: パターン分類、修正対象を特定
4. **Phase C**: パターン別に修正実施

### 効率化のポイント

- **B-1 調査**: Glob + Grep で自動検索
- **B-2 実装確認**: テストファイルが存在するか確認、テストメソッド数をカウント
- **パターン分類**: Excel/CSV 作成、手作業分類は最小限
- **C 実装**: 修正対象を絞り込み、優先度順に実施
