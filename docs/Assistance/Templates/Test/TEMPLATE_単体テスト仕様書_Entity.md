# 単体テスト仕様書テンプレート — Entity

**プロジェクト:** SupportAdvance  
**テスト対象:** Entity（エンティティ）  
**テストレベル:** 単体テスト  
**版:** 1.0 / 2026-05-22

---

## 0. 本書の位置づけ

本書は、Domain層の Entity クラスが、設計書で定義された
**ビジネスルール・状態遷移・不変条件・ドメインロジック** を満たすことを確認するテスト仕様書。

---

## 1. テスト目的

Entity の各メンバーが、以下の仕様を満たすことを確認する：

- **識別性**：ID による一意性の確保
- **生成ロジック**：ファクトリメソッド / コンストラクタが正しく機能
- **状態遷移**：業務ルールに基づいた状態変更
- **不変条件**：違反する操作は例外発生
- **ドメインロジック**：ビジネスルール実装の正確性

---

## 4. テスト観点別の検証シナリオ

### 観点 EN-CR-01：ファクトリメソッドで Entity が生成される

#### 4.1.1 テスト観点

Entity のファクトリメソッド（Create など）で、正しくインスタンスが生成される。

#### 4.1.2 テストパターン

| パターン | 分類 | 説明 |
|---------|------|------|
| 4.1.2.1 | 正常系 | 通常の注文生成 |
| 4.1.2.2 | 正常系 | 複数フィールドでの生成 |

#### 4.1.3 前提条件

- ファクトリメソッドが定義されている
- 必須フィールドが準備されている

#### 4.1.4 テストデータ

| パターン | 入力値 | 説明 |
|---------|--------|------|
| 4.1.2.1 | customerId="CUST-001", items=[...] | 基本的な注文データ |
| 4.1.2.2 | customerId="CUST-001", items=[...], memo="..." | オプションフィールド付き |

#### 4.1.5 期待結果

| パターン | 期待値 | 検証項目 |
|---------|--------|---------|
| 4.1.2.1 | order != null | インスタンスが生成される |
| 4.1.2.2 | order.Id != null | ID が生成される |

#### 4.1.6 判定基準

- [ ] ファクトリメソッドでインスタンスが生成される
- [ ] null ではなく有効な Entity が返される
- [ ] ID が自動採番される（後述 EN-CR-02）

---

### 観点 EN-ST-02：不正な状態遷移で例外が発生する

#### 4.2.1 テスト観点

ビジネスルール上許可されない状態遷移を試みた場合、例外が発生する（異常系テスト）。

#### 4.2.2 テストパターン

| パターン | 分類 | 説明 |
|---------|------|------|
| 4.2.2.1 | 異常系 | Created から Shipped へ直接遷移（Skip） |
| 4.2.2.2 | 異常系 | Cancelled からの遷移試行 |
| 4.2.2.3 | 異常系 | 同じ状態への遷移試行 |

#### 4.2.3 前提条件

- Entity が Created 状態で存在する
- 状態遷移メソッドが実装されている

#### 4.2.4 テストデータ

| パターン | 入力値 | 説明 |
|---------|--------|------|
| 4.2.2.1 | order.Status = Created → order.Ship() | 不正な遷移 |
| 4.2.2.2 | order.Status = Cancelled → order.Approve() | キャンセル後の操作 |
| 4.2.2.3 | order.Status = Created → order.Create() | 既存状態への操作 |

#### 4.2.5 期待結果

| パターン | 期待例外 | メッセージ | 検証項目 |
|---------|--------|---------|---------|
| 4.2.2.1 | InvalidOperationException | "Cannot ship from Created status" | 例外発生 |
| 4.2.2.2 | InvalidOperationException | "Cannot operate on Cancelled order" | 例外発生 |
| 4.2.2.3 | InvalidOperationException | "Already in Created status" | 例外発生 |

#### 4.2.6 判定基準

- [ ] 不正な状態遷移で例外が発生する
- [ ] 例外メッセージが明確である
- [ ] Entity の状態が変更されない（トランザクション性）

---

### 観点 EN-BR-02：ルール違反で例外が発生する

#### 4.3.1 テスト観点

ビジネスルール（例：注文額の最小値）を違反する操作は、例外で拒否される（例外発生テスト）。

#### 4.3.2 テストパターン

| パターン | 分類 | 説明 |
|---------|------|------|
| 4.3.2.1 | 例外発生 | 注文額が 0 円未満 |
| 4.3.2.2 | 例外発生 | 注文アイテムなし |
| 4.3.2.3 | 例外発生 | 金額が最大値を超過 |

#### 4.3.3 前提条件

- ビジネスルールが定義されている
- バリデーションメソッドが実装されている

#### 4.3.4 テストデータ

| パターン | 入力値 | 説明 |
|---------|--------|------|
| 4.3.2.1 | amount = -100 | 負の金額 |
| 4.3.2.2 | items = [] | 空のアイテムリスト |
| 4.3.2.3 | amount = 999999999 | 異常な大きさ |

#### 4.3.5 期待結果

| パターン | 期待例外 | メッセージ | 検証項目 |
|---------|--------|---------|---------|
| 4.3.2.1 | ArgumentException | "Amount must be positive" | 例外発生 |
| 4.3.2.2 | ArgumentException | "Order must have at least one item" | 例外発生 |
| 4.3.2.3 | ArgumentException | "Amount exceeds maximum limit" | 例外発生 |

#### 4.3.6 判定基準

- [ ] ルール違反で例外が発生する
- [ ] 例外の型が適切である（ArgumentException 等）
- [ ] エラーメッセージが明確である

---

### 観点 EN-BR-04：境界値でのルール適用が正しい

#### 4.4.1 テスト観点

ビジネスルールの境界値（例：最小金額 1 円、最大金額 999,999 円）で正しく機能する（境界値テスト）。

#### 4.4.2 テストパターン

| パターン | 分類 | 説明 |
|---------|------|------|
| 4.4.2.1 | 境界値 | 最小値 - 1（失敗） |
| 4.4.2.2 | 境界値 | 最小値（成功） |
| 4.4.2.3 | 境界値 | 最大値（成功） |
| 4.4.2.4 | 境界値 | 最大値 + 1（失敗） |

#### 4.4.3 前提条件

- ビジネスルール：注文額は 1 円 ～ 999,999 円

#### 4.4.4 テストデータ

| パターン | 入力値 | 説明 |
|---------|--------|------|
| 4.4.2.1 | amount = 0 | 最小値未満 |
| 4.4.2.2 | amount = 1 | 最小値 |
| 4.4.2.3 | amount = 999999 | 最大値 |
| 4.4.2.4 | amount = 1000000 | 最大値超過 |

#### 4.4.5 期待結果

| パターン | 期待値 | 検証項目 |
|---------|--------|---------|
| 4.4.2.1 | ArgumentException | 例外発生 |
| 4.4.2.2 | order.Amount = 1 | 成功 |
| 4.4.2.3 | order.Amount = 999999 | 成功 |
| 4.4.2.4 | ArgumentException | 例外発生 |

#### 4.4.6 判定基準

- [ ] 境界値の手前で例外が発生する
- [ ] 境界値そのものは成功する
- [ ] 一貫した判定がなされている

---

### 観点 EN-ST-05：複数の状態遷移が正しく機能する

#### 4.5.1 テスト観点

複数の状態遷移が連続して発生する場合、状態機械が正しく機能する（状態遷移テスト）。

#### 4.5.2 テストパターン

| パターン | 分類 | 説明 |
|---------|------|------|
| 4.5.2.1 | 状態遷移 | Created → Approved → Shipped → Delivered |
| 4.5.2.2 | 状態遷移 | Created → Cancelled |

#### 4.5.3 前提条件

- Entity が Created 状態で存在する
- 各状態遷移メソッドが実装されている

#### 4.5.4 テストデータ

| パターン | 入力値 | 説明 |
|---------|--------|------|
| 4.5.2.1 | 順序：Create → Approve → Ship → Deliver | 通常フロー |
| 4.5.2.2 | 順序：Create → Cancel | キャンセルフロー |

#### 4.5.5 期待結果

| パターン | 期待値 | 検証項目 |
|---------|--------|---------|
| 4.5.2.1 | Status = Delivered | 最終状態が正しい |
| 4.5.2.1 | (create時刻) < (approve時刻) < ... | タイムスタンプ順序 |
| 4.5.2.2 | Status = Cancelled | キャンセル状態 |

#### 4.5.6 判定基準

- [ ] 複数の遷移が連続して成功する
- [ ] 最終状態が期待通りである
- [ ] タイムスタンプが記録される
- [ ] ロールバック時に初期状態に戻る

## 5. 判定基準

### 5.1 全般的な判定基準

| 項目 | 基準 |
|------|------|
| **生成** | ファクトリメソッドで正しく Entity が生成されること |
| **状態遷移** | 有効な遷移のみが許可され、無効な遷移で例外が発生すること |
| **ビジネスルール** | ルール違反が正しく検出されること |
| **不変条件** | 違反が防止されること |

### 5.2 検証方法

```
【EN-CR 観点の検証】
  var order = Order.Create(customerId, items);
  Assert.NotNull(order);
  Assert.NotNull(order.Id);

【EN-ST 観点の検証】
  var order = Order.Create(...);
  order.Approve();
  Assert.Equal(OrderStatus.Approved, order.Status);
  // 不正な遷移
  Assert.Throws<InvalidOperationException>(() => order.Ship());

【EN-BR 観点の検証】
  Assert.Throws<ArgumentException>(() => 
    Order.Create(customerId, items, amount: -100));

【EN-CV 観点の検証】
  var order = Order.Create(...);
  Assert.True(order.IsValid());  // 不変条件チェック
```
